1. **如何使用**头条周简报？

## 如何使用（两条入口别混）

| 按钮 | 依赖 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| **规则提炼** | **不需要数据库**（纯前端/纯函数） | 把你粘贴的 DeepSeek「问题—改善—收益」长文，压成结构化草稿 | 不是海铭德「指标周报」，也不会读 Excel |
| **从指标周报生成问题骨架** | **必须能连上数据库** | 读取当周已保存的 `/weekly-summary` 指标（`WeeklyReport.metrics`），自动填「问题」结论句 | 不生成完整叙事周报；改善/收益仍要你补 |

### 推荐操作顺序

1. （可选）先在 `/weekly-summary` 导入 Excel、保存当周指标周报。  
2. 打开 `/headline-brief`，选对「本周/上周」。  
3. **主路径**：粘贴 DeepSeek 长文 → 点「规则提炼」→ 人工改稿 → 预览 → 复制 / 推送企微 / 下载海报 → 保存。  
4. **辅助路径**：若当周指标已入库，可点「从指标周报生成问题骨架」只补「问题」骨架，再粘贴长文提炼改善/收益，或手写。

> 说明：「规则提炼」生成的是**叙事精简稿**（问题—改善—收益），与「周报生成」页的**指标周报**是两个模块，只是预览都像「周报文案」。

---

## 原因（根因）

报错核心只有一句：

**应用连不上 `.env` 里配置的 PostgreSQL：`127.0.0.1:5432`。**

- 「规则提炼」走本地纯函数，**不查库**，所以能成功，看起来像「已经生成了周报」。  
- 「从指标周报生成问题骨架」会执行 `prisma.weeklyReport.findFirst(...)`，**必须读库**；库未启动 / 端口不通 / 地址配错时，就会抛出上述 Prisma 错误。  
- 另外：即便数据库稍后恢复，若尚未执行 schema 同步，保存简报还可能因缺少 `HeadlineBrief` 表失败（本阶段新增模型）。

这与业务逻辑写错无关，是**本地/当前环境的数据库连通性**问题。

---

## 解决方案

### 1. 先确认本机 Postgres 是否在跑（最常见）

在 PowerShell 中检查 5432 端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 5432
```

若 `TcpTestSucceeded : False`：

- 启动本机 PostgreSQL 服务（服务名常见为 `postgresql-x64-xx`），或  
- 用你平时连内网库的方式把数据库拉起来。

再确认 `.env` 中 `DATABASE_URL` / `DIRECT_URL` 指向**当前真实可达**的库（现在指向 `127.0.0.1:5432`）。若应连云端/内网其它地址，改回正确连接串后重启 `npm run dev`。

### 2. 同步表结构（库通了之后做一次）

```bash
npx prisma db push
```

确保存在 `WeeklyReport`（旧）与 `HeadlineBrief`（新）表。

### 3. 再验证「问题骨架」按钮

1. 先在 `/weekly-summary` 保存过**同一自然周**的指标周报。  
2. 回到 `/headline-brief` 同一周，点「从指标周报生成问题骨架」。  
3. 若当周没有已存指标，应看到友好提示「当周尚未保存海铭德指标周报…」，而不是数据库连接错误。

### 4. 若暂时不方便连库

- **只用「规则提炼」即可完成主流程**（粘贴 → 改稿 → 复制/海报）。  
- 「推送企微 / 按周保存 / 问题骨架」都依赖数据库，需等库恢复后再用。

## 回复（追加）

### 1. 「从指标周报生成问题骨架」还有意义吗？

有，但是**辅助能力，不是主路径**。

| | 规则提炼（主路径） | 问题骨架（辅助） |
| --- | --- | --- |
| 输入 | DeepSeek 叙事长文 | 当周已保存的海铭德**指标**（开卡数、车间占比、超期等） |
| 产出 | 问题 + 改善 + 收益 完整草稿 | **只填「问题」结论句骨架**（如「某车间占 59.8%」） |
| 价值 | 你现在的真实工作流 | 没贴长文时先有数字结论；或与指标周报对齐，减少「叙事和指标对不上」 |

你当前习惯是 DeepSeek 出全文再提炼 → **日常可以只用「规则提炼」**。骨架按钮适合：本周已在 `/weekly-summary` 存过表、还没写叙事、想先占住 Top 问题数字时用。觉得碍事可以先忽略，不挡主流程。

### 2. 库在服务器、不在本机 —— 怎么回事？

报错连的是本机 `.env` 里的 `127.0.0.1:5432`，说明**开发机当前指向本机库，而不是你的服务器库**。

处理：把本机运行 `npm run dev` 时的 `DATABASE_URL` / `DIRECT_URL` 改成**服务器 PostgreSQL 的真实地址**（或 SSH 隧道映射到本地后再指 `127.0.0.1`），改完重启 dev。  
「规则提炼」不查库所以一直能用；保存 / 推送 / 问题骨架才会撞库。

### 3. 要不要更新数据库表结构？

**要。** 本功能新增了表 `HeadlineBrief`（按用户+年+周存简报）。

在**能连上的那套库**上执行一次：

```bash
npx prisma db push
```

（或走你们正式的 migrate 流程。）  
不推表：提炼预览仍可玩；**保存简报会失败**。`WeeklyReport` 是旧表，骨架按钮依赖它里已有当周数据，一般不用为骨架单独加字段。

### 4. 对你这份 QC 样例 + DeepSeek 指令的建议

你贴的 QC 文已经比生产样例更「分类清晰」，规则提炼能吃；但收益是 4 条并列，而工作台硬约束是**生产/质量/管理各 1 句** —— 提炼后请人工把 4 条收益收成 3 类各一句。

## 回复（追加 · 预览可编 / 海报可复制 / 视觉建议）

对照样张：`docs/rcfs/头条周简报-W37-production-p1.png`（W37 生产头条）。

### 1. 右侧预览能否支持编辑？

**可以，而且应该做。** 当前右侧是「只读 Markdown 渲染」，左侧才是结构化表单；你要改一两句时被迫回左侧找字段，体验割裂。

**建议产品行为（后续改版）：**

- 右侧改为**可编辑纯文本/Markdown 源**（textarea），改完实时同步到「推送用文案」与字数校验。
- 与左侧结构的关系二选一（推荐 A）：
  - **A. 预览为「最终稿」优先**：右侧改动只影响 `markdownContent`（推送/复制），不回写结构字段；左侧再点「规则提炼」会覆盖草稿——适合领导汇报微调。
  - **B. 双向同步**：右侧改完尝试反解析回结构（易碎，QC/生产格式一变就炸）——不建议做主方案。
- 增加「从预览重置为结构生成稿」按钮，避免改乱后无法回到干净版。

你现在的临时办法：在左侧对应字段改 → 右侧预览自动变；或复制预览到别处改完再粘回（尚未支持粘回）。

### 2. 海报应支持复制？

**同意，发群场景里「复制」往往比「下载再选图」更快。**

可行实现（浏览器限制下的务实方案）：

| 能力 | 说明 |
| --- | --- |
| **复制图片到剪贴板** | `ClipboardItem` + `image/png` blob；Chrome/Edge 桌面端可用，部分环境需 HTTPS；失败则 toast 提示改用下载 |
| **复制失败兜底** | 保留「下载 PNG」；可选「先下载再手动粘贴」引导 |
| **复制文案** | 已有 Markdown 复制；海报侧再加「复制同款纯文本」可选 |

结论：下一期海报区应并排 **「复制图片」+「下载 PNG」**，复制失败不阻断下载。

### 3. 海报视觉——按样张的切实改进建议（可落地，非空泛审美）

当前问题（对照 W37 样张）可概括为：**「开发默认页」而不是「汇报海报」**——灰底、顶条细线、字号匀质、无分区节奏、底部被裁切、信息密度像把 Markdown 直接贴进画布。

#### 诊断（为什么显得丑 / 难读）

1. **没有「第一眼层级」**：标题「头条周简报 · 生产头条」与正文字重、字号接近，领导扫一眼抓不住「第几周、哪个模块」。
2. **章节不分区**：问题 / 改善 / 收益挤在同一灰平面，缺少色条、卡片或分隔节奏。
3. **证据行过长**：高频句仍是长段落，手机屏上变成「墙字」，违背「10–20 秒可读」。
4. **页脚被硬切**：管理收益等句子截断，发群显得半成品。
5. **视觉语言单薄**：仅顶部一条细色带 + 系统字体堆字，缺少品牌锚点、数据强调、留白节奏。

#### 可执行的设计规范（建议直接写成海报 v2 规格）

**画布与安全区**

- 尺寸固定 **1080×1920**（或 720×1280 的 1.5× 清晰版），边距 ≥ 48px；底部预留 **120px** 给「说明/定性」与品牌脚注，禁止正文顶死底边。
- 内容超高：**自动缩字或分页**，禁止半句截断；第 2 页只续「改善/收益」，首页必须打完「问题」结论。

**信息架构（一屏三块）**

```text
┌ 顶栏：模块名 + 第N周 + 日期区间（大）     ┐
│ 副标：问题—改善—收益（小、弱）            │
├ 块A 问题：2–3 条结论卡（深字+浅底）       ┤
│   每条下最多 3 个「标签芯片」而非长句     │
├ 块B 改善：竖向编号列表（短句）            ┤
├ 块C 收益：三列或三行「生产/质量/管理」    ┤
└ 脚注：定性说明 + 生成日期（灰、小）       ┘
```

**字体与层级（中文汇报向）**

- 标题：明确中黑/半粗，**34–40px**；周次日期：**28–32px**。
- 章节名「一、问题」：用**色条+白字小胶囊**或左侧 6px 色条，不要再用与正文同级的加粗一行。
- 正文：**24–26px**，行高 1.45；证据改为 **13–14px 标签**（圆角芯片，浅底深字）。
- 避免整页同一字号「贴字」；同一屏最多 **4 级**字号。

**色彩（克制、可打印、非模板紫）**

- 底：近白 `#F7F8FA` 或极浅冷灰，不要大面积死灰。
- 主色：选一个业务色并只用在顶栏/章节条（如生产用青绿 `#0F766E`，QC 用靛蓝 `#1D4ED8`）——**模块换色，版式不变**。
- 收益块可用极浅三色底区分生产/质量/管理（饱和度要低，发群不花）。
- 禁止：大面积渐变炫光、玻璃拟态、emoji 装饰、多阴影叠罗汉。

**内容排版规则（比换皮肤更重要）**

- 问题结论：**一行说完**；机台流水、长因果移出海报（留在 Markdown）。

## 方案征询（海报换行 / 单图 / 多模块）— 待你勾选，同意前不编码

### 根因（先对齐事实）

1. **过早换行**：海报正文目前用「按固定汉字个数折行」（如约 28 字一刀），**不是**按画布真实像素宽度测量。中英混排、标点多时，明明一行还空着一大截就断了；「最集 / 中」被切开就是这个原因。
2. **双编号 1. 1.**：结构字段标题里往往已带 1.，绘制时又前缀了一次 1.。
3. **被截断/缺下半句**：固定字数折行 + 卡片高度估算偏紧时，第二行可能画不全或视觉上像「没接上」。
4. **多页 p1/p2**：当前按「单模块内容权重」可能拆成 2 页；且导出按钮只画**当前选中模块**，不是把生产+QC自动拼进同一张。
